## Architecture & technical decisions
1. Internal canonical symbol is the plain string "XAUUSD". Provider-specific
   symbols are mapped, never used internally: tradingview "OANDA:XAUUSD",
   oanda "XAU_USD", csv "XAUUSD".
2. TradingView is charting/display ONLY. Integration = the free official
   TradingView embeddable Advanced Chart widget (script embed), which is the
   supported no-license-required method. No scraping; TV data never feeds the
   analysis/trading pipeline. Machine data comes from the CSV replay dataset
   (and, when configured by the operator, a licensed REST provider).
3. TradingView consumer accounts offer no generic OAuth for bots; therefore
   NO "Sign in with TradingView" is implemented (fake auth is prohibited).
   Broker auth = OANDA v20 personal access token (Bearer), stored only via
   env/config, never in DB plaintext.
4. Live execution = direct broker API (OANDA v20 REST), defaulting to
   practice (sandbox/demo) host. Live requires: connected broker account +
   explicit typed confirmation + settings validation. Paper and live adapters
   are separate code paths; engine mode gates which one receives orders.
5. Analysis confidence is a heuristic 0-100 score with explanation strings;
   it is NOT presented as a calibrated probability.
6. Fundamental data is modelled but reports "unavailable" unless the operator
   configures a licensed provider; missing data never fabricates analysis.
7. Migrations are additive (new tables only); no existing data is dropped.
